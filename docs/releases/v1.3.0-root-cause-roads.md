# v1.3.0 Phase A — Missing roads root cause

**Date:** 2026-10-20  
**Status:** Diagnosed and repaired

## Symptom

Zooming into CT / cities showed empty pastel land/water (no streets, highways, or labels).

## Evidence

1. Browser network loaded both `tiles.openfreemap.org/styles/dark` **and** `demotiles.maplibre.org/style.json`.
2. Almost no OpenMapTiles planet `*.pbf` vector tiles were requested after style switch.
3. `GET /api/v1/map-styles` returned:

```json
"styleUrl": "https://demotiles.maplibre.org/style.json"
```

for both `standard` and `dark`.

4. `@magnexis/provider-adapters` **source** already defaulted to OpenFreeMap, but **`dist/`** still exported the old demotiles default.
5. The API (`tsx` → package `main: ./dist/index.js`) resolved the stale dist.
6. `MapCanvas` on load replaced the client OpenFreeMap style with the API URL whenever they differed — permanently switching to demotiles.

OpenFreeMap’s dark/liberty styles correctly reference OpenMapTiles `transportation` / `transportation_name` and return CT tiles HTTP 200 when requested directly.

## Repair

1. Rebuild `provider-adapters` so dist matches OpenFreeMap defaults.
2. Harden `resolveMapStyles` to never accept demotiles as a default or available basemap.
3. Harden `MapCanvas` to refuse demotiles URLs from the API.
4. Sync Horizon zoom/locate store updates into the MapLibre camera (controls previously only mutated Zustand).
5. **Secondary defect:** OpenFreeMap `dark` paints motorways/`minor` roads as `#000` / `#181818` on `rgb(12,12,12)` — tiles loaded but roads were invisible. Magnexis **RoadAtlas** paint overrides (`applyRoadAtlasPaints`) restore high-contrast highway/street colors after `style.load`.

## Verification

- `/api/v1/map-styles` returns OpenFreeMap liberty/dark URLs.
- Browser loads `planet/.../*.pbf` tiles.
- At city/neighborhood zoom, motorways and local streets are clearly visible (RoadAtlas night/standard paints).
